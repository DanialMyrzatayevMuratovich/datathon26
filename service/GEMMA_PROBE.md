На время эксперимента wrapper держит [SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate) SYSTEM+DISPLAY_REQUIRED, возвращая предыдущее состояние в finally. Для второго прогона задана grammar A/B/C/D: это ограничение синтаксиса; D сохраняет возможность неопределённого ответа. В runtime-отчёт добавлены SHA256 фактических JPEG-входов и вопросов. После исправления wrapper также сохраняет их после каждого успешного запроса в `.inputs.jsonl`, чтобы timeout не уничтожал provenance завершённых вызовов. Это позволяет проверять совпадение входов при дальнейшем сравнении; изображения и свободные ответы не экспортируются.

Подготовлена поддержка одного большего кандидата — [официального E4B QAT GGUF](https://huggingface.co/google/gemma-4-E4B-it-qat-q4_0-gguf), revision `4b4a2c1d584be7264f87aac328a1bc739ce81b6c`,6 146 493 536байт. ## Воспроизведение

На подготовленном Windows-хосте запустить в отдельном PowerShell из корня repo:

```powershell
& '..\local_ml\llama-b11715\llama-server.exe' -m '..\models\gemma-4-e2b-it-qat-q4_0\gemma-4-E2B_q4_0-it.gguf' --mmproj '..\models\gemma-4-e2b-it-qat-q4_0\gemma-4-E2B-it-mmproj.gguf' --host 127.0.0.1 --port 8091 --alias gemma-4-e2b-it-qat-q4_0 -c 4096 -np 1 -ngl 20 --mmproj-offload --image-min-tokens 560 --image-max-tokens 560 --cache-ram 0 --no-cache-idle-slots --offline --no-context-shift -t 2 -tb 2 --reasoning off --reasoning-budget 0
```

После `/health` = ok, в другом терминале:

```powershell
uv run python -m service.local_vlm_probe --only X-1,X-3,X-4,X-5,X-13,X-19,X-44,X-37 --videos data/raw/open/open/videos --out runs/jobs/gemma-e2b-gpu-20261018/t9-balanced.json --every 4 --max-calls 40 --budget-sec 1200
```

Нужны существующие зависимости проекта, FFmpeg/ffprobe и локальный `../models/grounding-dino-tiny` закреплённой проектом ревизии. Сначала закрыть другие тяжёлые jobs. После прогона остановить **свой** llama-server через Ctrl+C. Дедлайн wrapper завершает Python/FFmpeg и очищает собственный scratch, но не управляет сервером, запущенным в другом терминале. После timeout/failure также остановить сервер перед следующим экспериментом.

Эксперимент обращается только к127.0.0.1, игнорирует HTTP proxies, запрещает redirects; загрузка моделей offline, банковские кадры остаются локально. Родитель проверяет SHA256 подготовленных весов, но identity работающего сервера нужно подтверждать отдельно. В выполненном запуске рядом сохранены PID, executable, точные аргументы и хеши executable/DLL (`server-launch.json`).

## Отдельная проверка видимого состояния ключа

Добавлены `service/local_state_probe.py` и `service/prepared_state_probe.py`: пять равномерных окон по три кадра за2с, существующая локализация safe/door, фактические состояния A/B/C/D. Без меток, выбора правильного ответа по имени и юридических вердиктов. D означает неопределённость, не «нарушений нет». Ошибка запроса даёт failed с сохранением завершённых окон и только типом исключения; `runs/.hot` блокирует replay. PNG/JPEG/prompt hashes проверяются до первого запроса и сверяются с реально отправленными изображениями.

Для Windows с малым RAM — две фазы. Сначала остановить собственный VLM-server, затем:

```powershell
uv run python -m service.prepared_state_probe prepare --mode key --videos data/raw/open/open/videos --only X-22,X-23,X-29 --out runs/jobs/gemma-key-prepared-20261018
```

Каталог должен быть новым. После успешного выхода detector-процесс завершён. Запустить проверенный E4B server той же командой выше, заменив E2B на E4B в обоих путях и alias. Обязательно дождаться `/health` = ok; 503 Loading model не готовность. Затем:

```powershell
uv run python -m service.prepared_state_probe infer --inputs runs/jobs/gemma-key-prepared-20261018 --out runs/jobs/gemma-e4b-key-20261018-retry.json --model gemma-4-e4b-it-qat-q4_0 --port 8091
```

Обе фазы ограничены600с через supervisor, который завершает собственный Python/FFmpeg. Отдельный llama-server после прогона/failure остановить вручную. Replay импортирует PIL и HTTP-клиент, без torch/DINO. Его время исключает отдельную подготовку и запуск весов; это не SLA видео. PNG остаются в локальном ignored каталоге. Все тестовые изображения в тестах синтетические.

Фактический E4B key-screen: `runs/jobs/gemma-e4b-key-20261018-retry.json`,3/3 видео,15/15 запросов, все15 — D (ключ/замок неразличим уверенно), медиана4.766с, replay72.832с. Это **не**15 правильных отрицательных ответов и не исправленный T3. Первый запуск получил503, пока сервер загружался, и завершился failed с0 успешных вызовов; он сохранён отдельно. Повтор начат только после health=ok. После завершения сервер остановлен. Доказательств в пользу замены production Qwen нет.

## Условия принятия

T9 action-probe различает ручной счёт, использование машинки, перемещение пачки и неопределённость. **Ручной счёт не равен автоматически нарушению; использование машинки не доказывает пересчёт всей пачки.** Он сам по себе не закрывает частичный пересчёт и не оценивает отсутствующие production-ветки T3/T13 и новую отдельную эвристику T6. `complete` означает завершение назначенных окон, не непрерывное наблюдение операции.

Переход в production возможен после реализации нужного правила и двух полных uncached40 с одинаковой разметкой, контроля всех19 чистых видео, совместного совпадения типа/времени и реального API/SLA. Для сравнения именно моделей должны совпадать JPEG-хеши, вопросы, окна и настройки генерации; иначе сравниваются два pipeline. 95%=38/40 development-вердиктов, ещё не подтверждено и не гарантирует результат на скрытых видео.
