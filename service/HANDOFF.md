## Что можно забирать

- R1–R3: `service.main:app`, MOV до 200 MiB, строгий публичный JSON, details/video/Range/HEAD. X-API-Key обязателен кроме health/UI, секреты не выводятся.
- R4: два отдельных процесса, 8 мест для загрузки/очереди/обработки, 270 с от постановки в очередь. Upload timeout 180 с / idle 15 с, 408 при зависании, 429 при заполнении. Лимит жюри <300 с проверяется CLI от начала загрузки; он не следует из одного внутреннего таймаута.
- Диск: failed остаётся в памяти, health/загрузки возвращают 503 до сохранения результата; запись повторяется, поток жив. TTL 24 часа также удаляет осиротевшие каталоги прерванных загрузок.
- На POSIX независимый watchdog завершает группу ML-процесса при исчезновении API или превышении deadline, включая нативный зависший inference. На Windows работающий API останавливает дерево через taskkill; настоящий ML-хост — Apple Silicon.
- CSP UI с `connect-src 'self'` блокирует отправку ключа произвольному `?api=`. Локальные ресурсы, Blob video, JPEG и внешние ссылки на нормы совместимы.
- `service.cli check --strict`: HTTP 200, точные поля, конечные неотрицательные таймкоды, согласованный вердикт, настоящий JPEG/base64, 8 проверок HTTP 401. Redirect с ключом запрещён. Exit 1 при failed/timeout/ошибке контракта.
- `service.cli doctor --engine real --require-ui`: проверка платформы и локальных весов; real без них не стартует. MODELS_DIR нормализуется для worker. Doctor не измеряет качество/скорость.
- R5/R9: README обновлён; отдельный Mac с launchd/Caddy подготовлен в [deploy/README.md](deploy/README.md). Генератор ничего не покупает/запускает, ключа в plist нет. Реальное развёртывание ещё не выполнено.
- После `4dbab5a`: API-worker удаляет `DT_CACHE` перед импортом движка. Кэш подбора правил остаётся для локальных экспериментов, но не используется при живой приёмке. Добавлен тест границы окружения.
