## 2. Инструкция по запуску и использованию

**Проверка видео через интерфейс** (раздел 4 ТЗ):
1. Откройте адрес сервиса, введите API-ключ в поле вверху страницы — браузер его запомнит.
2. Перетащите видео `.mov` в область загрузки или нажмите на неё и выберите файл → «Проверить видео».
3. Пока идёт анализ, видны загрузка файла и этапы: раскадровка → поиск событий → проверка по правилам → отчёт.
4. Итог: «Нарушение не обнаружено» или «Обнаружены признаки возможных нарушений». По каждому нарушению — тип, таймкод, окно события, описание, 1–3 кадра-доказательства (нажмите на кадр, чтобы увеличить) и нормативное основание: документ, пункт, дословная цитата, ссылка на adilet.zan.kz и пометка «прямая норма» или «трактовка».
5. Нажмите на таймкод или на окно на шкале под видео — плеер перемотает ролик к событию.

## 3. Архитектура, подход и модели

<!-- Черновик bigali по docs/ARCHITECTURE.md (a2b74fc) и service/HANDOFF.md. Абзац «Сервис» — REVIEW-OK asylbek 21:45; время и память — docs/METRICS.md, прогон runs/jury/20261017T2214-5d08 (7c0181e); остальное ждёт [REVIEW] danial. -->

**Подход: готовые открытые модели + правила, без обучения «с нуля».** В обучающем наборе 40 уникальных роликов и 1–5 примеров на тип нарушения — нейросеть, обученная на них, рисковала бы запомнить одну комнату и два её ракурса. Поэтому решение гибридное:

1. **Кадры.** Видео прореживается до 2 кадров в секунду.
2. **Сцена.** Grounding DINO по текстовому описанию находит стол, ноутбук и сейф. Зоны строятся от найденных объектов, а не от фиксированных координат экрана, — так решение рассчитано на смену положения камеры. Проверено на двух ракурсах обучающего набора; на новом ракурсе не проверялось (раздел 6).
3. **Люди.** RT-DETRv2 находит людей на каждом кадре. Лица не распознаются и не идентифицируются — используются только рамки «человек».
4. **Кто где.** Люди у рабочего места делятся по «глубине» в кадре (нижний край рамки). Кассир — группа, ближайшая к ноутбуку и сейфу; дальше он отслеживается от кадра к кадру. Сторона клиента — люди на другой глубине; правило не опирается на конкретный ракурс, но проверено только на двух ракурсах обучающего набора.
5. **События по правилам:** кассир ушёл с места, вошёл посетитель, двое на стороне кассира, клиент ушёл, а работа с деньгами продолжается и т. п.
6. **Проверка VLM.** Локальная Qwen3-VL-4B получает увеличенные вырезки кадров события (экран ноутбука, сейф, участки стола) и отвечает на точные вопросы «да/нет»: «на экране открыто рабочее окно?», «дверца сейфа открыта?», «на столе лежат купюры?». Ответы детерминированы (жадное декодирование).
7. **Отчёт.** Для каждого нарушения — тип из фиксированного списка, таймкод начала события, 1–3 JPEG-кадра, описание и норма из проверенного каталога `data/laws/rules_catalog.json`. Модель не генерирует ссылки на законы.

**Модели** — все открытые, коммерческое использование разрешено:

| Роль | Модель | Лицензия |
|---|---|---|
| Люди на кадрах | RT-DETRv2-R50 (`PekingU/rtdetr_v2_r50vd`) | Apache-2.0 |
| Предметы по тексту: стол, ноутбук, сейф, дверь, счётная машина, сумка | Grounding DINO tiny (`IDEA-Research/grounding-dino-tiny`) | Apache-2.0 |
| Ответы «да/нет» по вырезкам кадров | Qwen3-VL-4B-Instruct, 4 бита, MLX (`mlx-community/Qwen3-VL-4B-Instruct-4bit`) | Apache-2.0 |

Версии весов закреплены хэшами в `scripts/download_models.sh`. Ultralytics YOLO (AGPL-3.0) и модели без явной коммерческой лицензии сознательно не используются.

**Сервис.** FastAPI отдаёт и API, и веб-интерфейс с одного адреса; интерфейс — статические HTML/CSS/JS без CDN и внешних шрифтов. Каждое видео обрабатывается в отдельном процессе с лимитом времени: 2 процесса, до 8 видео в загрузке, очереди и обработке, 270 с от постановки в очередь. Принимается `.mov` до 200 МБ; ключ `X-API-Key` обязателен для всех запросов, кроме проверки доступности и самой страницы.

**Скорость и память.** Через API на реальной модели без кэша обработаны все 40 обучающих роликов, по одному: от загрузки до результата — **34–120 с** на видео (медиана 61 с) при лимите ТЗ 300 с, сбоев 0 (`runs/jury/20261017T2214-5d08`). На Mac с 16 ГБ памяти два процесса уводят систему в подкачку (своп 5,4 → 12,2 ГБ за 30 с), поэтому на нём работает **один процесс**, и одновременно загруженные видео обрабатываются по очереди.

**Где работает.** Основной хост — Mac на Apple Silicon: Qwen через MLX на GPU Apple, детекторы через PyTorch. **Перенос на Linux-сервер с GPU NVIDIA — план, не реализован:** MLX работает только на Apple Silicon, для CUDA нужно заменить слой `vision/vlm.py` на ту же Qwen3-VL-4B через PyTorch; детекторы и остальной код не меняются.

**Локальность.** Обработка видео целиком локальная: облачные AI-сервисы и внешние API не используются, после загрузки весов интернет не нужен (раздел 7 ТЗ).

### Принцип сопоставления
1. Тип нарушения — только то, что **видно** на видео: действие или его отсутствие (кассир ушёл, сейф открыт, сумку не осмотрели). Выводы, для которых нужны невидимые данные — проводки, сверки, содержимое документов, — сервис не делает (раздел 7 ТЗ).
2. Каждому типу соответствует пункт акта и **дословная** цитата из официального текста; каталог — `data/laws/rules_catalog.json`, обоснование по типам — `docs/LAWS.md`.
3. Пометка основания: **«прямая норма»** — пункт прямо требует того, что видно на видео; **«трактовка»** — пункт описывает требование, с которым увиденное может расходиться. В описании нарушения это отражено словами: «Нарушен п. …» для прямой нормы и «Может противоречить п. …» для трактовки.
4. Результат — подсказка проверяющему с кадром и таймкодом, а не юридическое заключение.

В строках «Тип» и «Таймкод» они оцениваются независимо друг от друга; строка «вместе» — строже: `uv run python -m service.quality runs/jury/20261017T2214-5d08/predictions.json`.

### Известные случаи ошибок
Все 6 пропусков (одинаковы в обоих прогонах):
- **T3 «Ключ оставлен в замке сейфа» не распознаётся** (Х-22): ключ занимает несколько пикселей; ни VLM, ни детектор объектов его не видят — 0 из 3 положительных вырезок в эксперименте Э1 (`docs/METRICS.md`).
- **T6 «Дверь кассы не закрыта» не распознаётся** (Х-32, Х-33): VLM не различает открытую и закрытую стеклянную дверь ни по узкой, ни по широкой вырезке (эксперименты Э2, Э3).
- **T13 «Деньги приняты без показа или просмотра УД» не распознаётся** (Х-2): ответы VLM «клиент показывает документ?» на нарушении и на чистых роликах отличаются на один ответ — это шум (эксперимент Э3).
- **T9 пропущен** (Х-44): пересчитана только часть пачки, движок этого не различает.
- **T7 «Посторонний» пропущен** (Х-18): посторонний у двери по рамкам «человек» неотличим от очереди клиентов.

### Что не проверено
- **Новый ракурс.** Финальное видео жюри снято под другим углом. Зоны строятся от найденных объектов, а не от координат кадра, но на видео под новым углом движок пока не проверялся.
- **Несколько видео одновременно.** По одному каждое видео укладывается в 34–120 с, но 5 одновременных загрузок на реальной модели не прогонялись. На Mac с 16 ГБ работает один процесс, поэтому видео ждут в очереди; по оценке (5 × ~60 с) пятое получит результат через ~4–5 минут — впритык к лимиту ТЗ в 5 минут.
- **Платформа.** Реальная модель сейчас работает только на Mac с Apple Silicon (MLX); запуск на Linux с NVIDIA не реализован (раздел 3).

### Общие ограничения
- Результат — подсказка для проверяющего, а не заключение: решение о нарушении принимает человек (раздел 7 ТЗ).
- Анализ только визуальный: звук не используется, лица не распознаются и не идентифицируются.
- Нарушения, для проверки которых нужны невидимые на видео данные (проводки, системная сверка, содержимое документов), сервис не утверждает.
- Видео обучающего набора закодированы в H.264 и воспроизводятся во встроенном плеере браузера. Файл в кодеке HEVC (H.265) браузер на Windows может не воспроизвести — интерфейс об этом сообщает; обработку таких файлов мы не проверяли.
