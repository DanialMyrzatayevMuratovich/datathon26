# Critics: свежие глаза на свою зону

Автор ангажирован к своему скору и своей истории. Критики работают со свежим контекстом и знают только задачу, контракт, результаты и твою зону.

1. Зона: `scripts/team.sh whoami`. Объём — файлы зоны, изменённые с начала: `git diff --stat $(git rev-list --max-parents=0 HEAD) -- <пути зоны>`, плюс лучший `runs/<run_id>/` и `docs/INSIGHTS.md`, `docs/PITCH.md`, если они твои.
2. Запусти **параллельно** четырёх критиков со свежим контекстом (Claude — субагенты, модель подешевле; Codex — его субагенты, если доступны, иначе по очереди). Каждому дай `docs/TASK.md`, `task.toml`, `docs/REQUIREMENTS.md` и пути. Каждый возвращает ≤ 5 находок: «файл:строка — проблема — исправление — крит / важно / мелочь», без воды.
   - **Утечка и валидация**: признаки, известные только после события; target в признаках через джойн или агрегат по всему набору; схема CV не повторяет боевое использование (время, клиенты); тюнинг на тех же фолдах, что и итоговая оценка; сдвиг train→test не учтён.
   - **Корректность кода**: признаки в `app/custom_features.py` считаются одинаково для train и test; джойны не плодят дубли строк; сабмит в формате ТЗ (строки, порядок id, колонки); падения на пропусках и новых категориях.
   - **Воспроизводимость**: свежий clone + README → та же метрика (`scripts/smoke.sh --with-data`); сиды; пути не абсолютные; всё нужное в git, сырые данные — нет.
   - **Утверждения**: каждая цифра в `docs/INSIGHTS.md`, `docs/PITCH.md`, `pitch/deck.md`, README подтверждается файлом из `runs/` или воспроизводимым расчётом; причинность не заявлена там, где есть только корреляция; бизнес-эффект помечен как оценка с допущениями.
   Вместо своих промптов для кода можно взять встроенные: Claude — `/code-review` и `/security-review`; Codex — `codex review`.
3. Сведи находки в одну таблицу по серьёзности. Исправь критичное и важное **в своей зоне**. Чужое — строкой в «Нужно от других» своего `docs/tasks/<id>.md` и `[REVIEW]` напарнику. После фриза мелочи не трогай.
4. Итог — в свой `docs/tasks/<id>.md` → «Готово»: «critics: найдено N, исправлено M»; владелец README перенесёт в `docs/TESTING.md`.
5. `scripts/checkpoint.sh "fix: critics findings (R-…)"`.
