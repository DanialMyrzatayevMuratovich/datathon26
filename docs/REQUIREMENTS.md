# Требования и план — AI-сервис выявления нарушений кассовой дисциплины по видео (ForteBank)

## Как мы поняли задачу
ForteBank хочет локальный сервис: проверяющий загружает видео с камеры над кассой → получает вердикт, а по каждому возможному нарушению — тип, таймкод, 1–3 кадра-доказательства, описание и пункт нормативного акта РК. Жюри прогоняет 5+ тестовых видео через **API** (автоматически) — поэтому API и вердикт важнее всего. Финальное видео — **другой ракурс**. Пропуск нарушения недопустим, ложных срабатываний — минимум. Всё локально, без облачных AI. Типы нарушений мы определили сами: `docs/VIOLATIONS.md` (12 типов), нормы — `docs/LAWS.md`.

## Контракт (меняет только лид)
Код контракта: **`contract/schemas.py`**. Вызов распознавания: **`vision.analyze(path, progress) -> VideoAnalysis`** (сейчас — заглушка, `VISION_ENGINE=mock`).

**Публичный API (жюри, строго по ТЗ, без лишних полей):**
- `POST /api/v1/analyze` — заголовок `X-API-Key`, multipart `file` (.mov) → `200 {"job_id": "3f2a9c1e"}`; 401 без ключа; 400 не видео; 413 > 200 МБ.
- `GET /api/v1/jobs/{job_id}` — `{"job_id","status","verdict","violations":[{"type","timecode_sec","description","evidence_frames":[{"timestamp_sec","image_base64"}]}]}`; пока `processing` — только `job_id` и `status`; 404 неизвестный job.

**Внутренний API (наш UI, можно без ключа или с тем же ключом):**
- `GET /api/v1/jobs/{job_id}/details` → `JobDetails`: прогресс, стадия, ошибка, полный `VideoAnalysis` (type_id, confidence, rules[act, approved, ref, quote, url, basis], why).
- `GET /api/v1/jobs/{job_id}/video` → загруженный файл (для плеера в UI).
- `GET /api/v1/health` → `{"ok": true, "engine": "mock|real"}`.

**Описание нарушения** (поле `description`) = «что видно» + «почему это может быть нарушением» + ссылка на пункт (`Нарушен п. 20 Правил (пост. НБРК от 29.11.2019 № 231).` / `Может противоречить …` для трактовок).

**Хранение:** загрузки и результаты — `runs/jobs/<job_id>/` (локально, в git не идут). Ключ — `.env.local` → `API_KEY=…`.

**UI:** статические файлы `ui/` (HTML/CSS/JS без CDN — сервис должен работать без интернета во внутреннем контуре банка), отдаёт тот же FastAPI → один URL.

## Допущения и вопросы менторам
- Как автоматическая проверка сравнивает `type` — строка целиком или по смыслу? (по умолчанию — фиксированные названия)
- Допустимы ли лишние поля в JSON? (по умолчанию — нет, только схема ТЗ)
- Таймкод «по бездействию»: ставим момент, когда действие должно было произойти (уход, вход).
- Когда жюри дёргает API (окно времени) и сколько видео одновременно?
- Можно ли хостить на ноутбуке команды через туннель?

## Риски
| Риск | Страховка |
|---|---|
| Ноутбук-хост уснул / упал во время проверки жюри | `caffeinate`, питание, второй хост (ноутбук Асылбека) с тем же кодом, быстрый перезапуск скриптом |
| VLM медленная → > 5 мин | VLM только на кадрах-кандидатах; лимит кадров; без VLM — вывод правил |
| Новый ракурс ломает зоны | зоны от найденных объектов (стол, сейф, дверь), а не от пикселей; проверка на своих роликах |
| Тип назван не так, как ждёт проверка | фиксированные названия, вопрос менторам |
| Ложные срабатывания | порог по оценке на 40 видео; описание без утверждений, которых не видно |
