# Решение на ночь 18.10: качество на новых видео, а не обещание 98%

Срез после `3a88b14` / `a3acc16`, около 00:20 по времени команды. Асылбек попросил конкретное решение; этот план не является измеренным улучшением. Фриз моделей — 18.10 в 08:00, сдача — в 12:00.

## Что действительно установлено

- Последняя полная последовательная real API-проверка `2214-5d08`: **34/40**, TP15/FN6/FP0/TN19. Совместное событие «тип + время ±2с» — **9/22**. 85% — доля верных вердиктов на development-наборе, не уверенность модели и не прогноз баллов жюри.
- Последние изменения `a3acc16` проверены на поднаборах: `2314-be18` — 14 видео на предыдущем engine hash; `2329-cad6` — 2 на текущем; `2331-8c4a` — шесть известных FN, **0/6 исправлено**, кэш включён. Полный результат текущего кода ещё надо измерить.
- Агенты не «обучили Qwen» своими объяснениями. `vision/vlm.py` загружает опубликованные pretrained-веса; дообученный на кейсе адаптер/LoRA в пути inference не обнаружен. Менялись вырезки, вопросы, пороги и Python-правила. Шпаргалка 30 сценариев не читается production-engine автоматически.
- Четыре из шести FN относятся к T3/T6/T13: **веток `Event` этих типов в production нет**. Их отклонили после слабых проб. T7 ограничен геометрией людей; T9 на обычной клиентской операции преимущественно включается после другого найденного события. Замена VLM не создаёт отсутствующие ветки.
- На ноутбуке Асылбека найдены **42 MOV** в `data/raw/open/open/videos`, все читаются FFprobe: H.264, **464×848**, 11.633–142.533с, суммарно 279.3 MiB. Путь отличается от ожидаемого; использовать явный `--videos`, файлы не перемещать. Это 40 уникальных примеров с учётом известных дубликатов.
- RTX3050 Laptop имеет **4096 MiB VRAM**; установлен `torch 2.14.1+cpu`, `cuda=False`; MLX/accelerate/bitsandbytes/llama_cpp и веса отсутствуют. Свободно около 117.6 GiB диска. Windows не сломан: текущий real backend написан для Apple Silicon. Переход на CUDA/GGUF требует отдельной установки, реализации и проверки, а не одного флага.

## Решение по модели

**Оставить текущую 4B контрольной моделью. Один ограниченный challenger — Qwen3.5-4B в MLX 4-bit на уже работающем Mac.** Не заменять весь pipeline до сравнения. На Windows пока выполнять проверку данных/метрик и подготовку новых сцен; перенос backend не делать главным критическим путём этой ночи.

| Вариант | Проверенные факты | Решение |
|---|---|---|
| Текущая Qwen3-VL-4B | Локальный рабочий pipeline; ограничения известны | Контроль и возможность отката |
| Qwen3-VL-8B | Уже проверена в Э1: сейф8/8, экран7/7, деньги3/6, ключ0/3 — как 4B; на этих запросах медленнее | Не обещать эффект от повторного простого увеличения размера |
| Qwen3.5-4B, MLX4bit | [Официальная multimodal-модель, Apache2](https://huggingface.co/Qwen/Qwen3.5-4B); [пакет MLX около3.06GB](https://huggingface.co/mlx-community/Qwen3.5-4B-4bit/tree/main) | Первый эксперимент после разрешения на загрузку, не готовое улучшение |
| Qwen3.5-9B, MLX4bit | [Официальная модель, Apache2](https://huggingface.co/Qwen/Qwen3.5-9B); [пакет около5.98GB](https://huggingface.co/mlx-community/Qwen3.5-9B-4bit/tree/main) | Только если первая проба полезна и остаётся время/RAM; один процесс |

Размер весов не равен RAM: нужны vision-активации, контекст, детекторы, кадры и ОС. На Mac16GB нельзя одновременно держать оба VLM и увеличивать workers. Модели большего класса и обучение с нуля не являются обоснованным бесплатным решением на оставшуюся ночь. Бесплатная лицензия не предоставляет бесплатный GPU и не гарантирует скорость.

**Ловушка интеграции Qwen3.5:** модель поддерживает thinking и по умолчанию может расходовать на него ответ. Сейчас `yes_no` даёт8 токенов и распознаёт ведущий yes/no. Не менять только `VLM_MODEL`: в экспериментальном адаптере отключить thinking (`enable_thinking=False`, см. [официальную карточку](https://huggingface.co/Qwen/Qwen3.5-4B)), проверить формат ответа и порядок нескольких картинок на синтетике. Проверить локальную совместимость через [mlx-vlm](https://github.com/Blaizzy/mlx-vlm), закрепить revision и сохранить исходный контроль. Новые зависимости/веса автоматически не устанавливались.

**Бюджет эксперимента, не обещание времени:** после загрузки отвести45–60мин одному challenger. На одинаковых входах проверить открыто/закрыто, человек в зоне/в очереди, считает/перекладывает и неразличимый объект; не только шесть положительных FN. Если нет улучшения при чистых контрпримерах, модель путает формат или сильно уходит в swap — прекратить эту ветку. Если есть эффект — полный прогон40, отдельные новые сцены, API и время/RAM; резерв ещё минимум2ч, фактическая длительность зависит от замеров. Загрузка3GB при1MB/s занимает около50мин, при10MB/s около5мин — это арифметика, скорость сети не измерена.

## Кто и что делает сейчас

**Даниал / агент:** не чинить шесть именованных файлов условиями по ID. Сначала полный контроль текущего кода, затем независимый положительный детектор действия T9 и трек кассира для S14/S23. Для T6 — различение геометрии/движения двери, а не повтор отвергнутого yes/no. Для T3 сначала подтвердить локально видимость ключа на исходном изображении: увеличение картинки не создаёт деталей. Для T13 не равнять отсутствие бумажного УД отсутствию идентификации. Испытание нового VLM отделить от изменений правил, чтобы понимать причину результата.

**Бигали / человек + агент:** ограничить интернет-поиск15мин. Затем12–16 собственных клипов по15–30с: пары «дверь закрыта/осталась открытой», «кассир ушёл/ещё работает», «деньги убраны/остались», «ключ виден/похожая ручка или блик», «клиент в своей зоне/пересёк границу». Для счётной машины нужна настоящая машина; имитацию движений нельзя объявлять эквивалентом проверки T9. Участники согласны на съёмку, деньги — реквизит.

Разделить **до просмотра моделью**: несколько сцен для разработки, остальные новые постановки/ракурс держать закрытыми до фиксированного сравнения. Не давать настройщику эти кадры, ответы и таймкоды. Соседние кадры, тот же исходный клип, его поворот или зеркалирование не являются независимыми данными. Собственная офисная постановка — маленький challenge-набор, не банковский независимый тест и не доказательство98% на жюри. Хранить факты/видимость отдельно от юридического вывода; неоднозначное не размечать как уверенное нарушение.

**Асылбек / агент:** данные найдены и технически проверены; доступен `service.quality_gate` для сравнения сохранённых прогнозов без вывода банковских описаний/кадров. Новые прогнозы сможет дать локальный real backend после загрузки/подключения модели, не сам текст плана. Доступа к терминалу Mac нет — команды выполняет агент Даниала.

## Как принимаем изменение

```bash
uv run python -m service.quality_gate --baseline runs/eval/20261017T2207-cebf --candidate runs/eval/20261017T2331-8c4a --out runs/jobs/night-quality-gate.json
```

Эта демонстрация **должна** сообщить недостаточность доказательств: старый контроль без нового manifest, кандидат — кэшированный поднабор6/40. `accuracy` полного набора для неполных прогнозов = null. Отчёт показывает TP→FN/TN→FP и потерянные совпадения каждого события при ±1/±2с, проверяет хеши labels/predictions и наличие provenance. Улучшение другого события не скрывает потерю прежнего. Он не читает видео, не подтверждает истинность вручную изменённого manifest и не проверяет текущий checkout против сохранённого source hash.

Для нового сравнения заменить пути на два полных uncached run на неизменных метках/видеофайлах. Даже `eligible_for_independent_evaluation` означает только готовность к отдельной проверке новых сцен: автоматического допуска в production нет. Регрессии не прятать общим процентом. Новые модели/правила после08:00 не вводить; сохранить лучший проверенный вариант и закончить сдачу.

FAQ требует5+ финальных видео и лимит5мин на видео; одновременная отправка пяти прямо не указана. Проверка очереди под нагрузкой — наша проверка надёжности, а не дополнительный выдуманный пункт ТЗ.

## Поле «Any additional materials … 1 file ≤100 MB»

Из этой фразы следует возможность приложить **один дополнительный файл**, а не требование обучить модель на дополнительном наборе и не разрешение публиковать банковские исходники. Практичный артефакт — собственное демо UI/API/объяснения на разрешённом видео. Формат проверить в самой форме; предложенный MP4 — только если форма принимает его.

Для3мин видео при2.5Mbit/s видеопоток около56MB; оставить запас и проверить фактический размер <90MB. Показать положительный случай, похожий допустимый случай и честное ограничение. Ни веса, ни все исходные банковские видео в этот файл не помещать. Это материал презентации, сам по себе accuracy не улучшает.
