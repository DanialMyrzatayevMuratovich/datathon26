# Проверка кассовых видео · DATATHON'26

Локальный анализ видео для ForteBank: MOV → вердикт → возможные нарушения с таймкодами, кадрами и нормативными основаниями. ТЗ: [docs/TASK.md](docs/TASK.md), контракт: [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

## Задача

Найти признаки возможных нарушений кассовой дисциплины по записи камеры над кассой. Проверяющий получает результат через API и самостоятельно проверяет кадры и ссылки на правила. Модели выполняются внутри развёрнутого сервисом хоста, без внешних AI API.

## Результат

Реализованы API, UI и движок распознавания. API включает ограниченную очередь, отдельные процессы обработки, ключ доступа, сохранение задач и удаление старых результатов. По умолчанию включён **`VISION_ENGINE=mock`**: это проверка интеграции, её вердикты не являются результатами распознавания. Текущий **real-движок требует macOS Apple Silicon и локальных весов MLX**. Частичные эксперименты danial: [docs/METRICS.md](docs/METRICS.md), архитектура: [docs/ML_SPEC.md](docs/ML_SPEC.md). Полная оценка качества и пяти реальных параллельных задач пока не подтверждена.

Публичный URL сдачи пока не зафиксирован. Для работы независимо от личных ноутбуков подготовлен [план отдельного Mac-хоста](service/deploy/README.md) с HTTPS и автозапуском. Аренда ещё не оформлена; URL назначают после приёмки. API-ключ передаётся жюри лично. Сводка проверки команды: [service/AUDIT.md](service/AUDIT.md).

## Главные инсайты

Типы нарушений и нормативные основания: [docs/VIOLATIONS.md](docs/VIOLATIONS.md) и [docs/LAWS.md](docs/LAWS.md). Выводы о качестве модели требуют отдельной оценки на размеченных видео.

## Как работает решение

```mermaid
flowchart LR
  user[UI или API-клиент] -->|MOV + X-API-Key| api[FastAPI: service/]
  api --> probe[Размер и ffprobe]
  probe --> queue[Очередь: максимум 8 задач]
  queue --> workers[2 отдельных процесса]
  workers --> vision[vision.analyze: модуль Даниала]
  vision --> storage[Видео и JSON: runs/jobs/]
  storage --> result[Статус, вердикт, кадры, правила]
  result --> user
```

Загрузка возвращает `job_id`, обработка идёт в фоне. Клиент опрашивает статус; публичный ответ соответствует `contract/schemas.py`, дополнительные поля для UI доступны отдельно. Таймаут от постановки в очередь — 270 секунд, затем процесс останавливается и задача получает `failed`. Завершённые результаты сохраняются при перезапуске; прерванные задачи получают `failed` с объяснением. Срок хранения — 24 часа.

## Технологии

Python 3.12, FastAPI, Pydantic, python-multipart, Uvicorn, FFmpeg/ffprobe, uv; туннель — cloudflared. Каталог норм: `data/laws/rules_catalog.json`. Модуль распознавания принадлежит danial, интерфейс `ui/` — bigali. Старый табличный набор `app/` не является API этого кейса.

## Установка и запуск

Нужны Git, uv и FFmpeg (`ffmpeg` и `ffprobe` в PATH). На Windows `.sh` запускаются в **Git Bash**. FFmpeg: `winget install --id Gyan.FFmpeg -e` на Windows; `brew install ffmpeg libomp` на macOS. После установки на Windows откройте новый терминал.

Из корня репозитория:

```bash
uv sync --frozen
uv run python -m service.cli init
bash scripts/run_service.sh
```

Все Python-зависимости, включая `python-multipart`, закреплены в lockfile. `init` создаёт случайный `API_KEY` в игнорируемом `.env.local`, не печатает и не заменяет существующий ключ. Страница: <http://127.0.0.1:8000/>; API: <http://127.0.0.1:8000/api/v1/health>. Остановка — Ctrl+C. Перед запуском скрипт вызывает `service.cli doctor --require-ui`; при неподходящей платформе или отсутствующих весах real-сервис не стартует.

| Переменная в `.env.local` | По умолчанию | Назначение |
|---|---|---|
| `API_KEY` | обязательна | Общий ключ; не передавать в URL |
| `VISION_ENGINE` | `mock` | `real` — macOS Apple Silicon с подготовленными весами |
| `MODELS_DIR` | `../models` относительно репо | Абсолютный путь к весам Даниала; генератор деплоя фиксирует его |
| `SERVICE_WORKERS` | `2` | Одновременные процессы анализа |
| `SERVICE_CAPACITY` | `8` | Максимум загрузок, ожидающих и работающих задач вместе |
| `SERVICE_TIMEOUT_SEC` | `270` | Очередь + обработка; максимум 270 секунд |
| `SERVICE_RETENTION_SEC` | `86400` | Срок хранения завершённых задач |
| `SERVICE_UPLOAD_TIMEOUT_SEC` | `180` | Максимальное время приёма тела запроса |
| `SERVICE_UPLOAD_IDLE_SEC` | `15` | Максимальная пауза между частями загрузки |
| `JOBS_DIR` | `runs/jobs` | Видео, результаты и журналы |

Uvicorn запускается с **одним** API-процессом: `uv run uvicorn service.main:app --host 127.0.0.1 --port 8000 --workers 1`. Параллельность анализа регулируется `SERVICE_WORKERS`. Блокировка каталога запрещает второму сервису использовать ту же очередь.

Для публичного адреса установите cloudflared (`winget install --id Cloudflare.cloudflared -e` / `brew install cloudflared`) и запустите `bash scripts/run_service.sh --tunnel`. HTTPS-адрес появится в выводе cloudflared. Quick Tunnel временный и меняется после перезапуска; перед сдачей нужен стабильный хост и согласованный URL. Для заранее настроенного named tunnel задайте `TUNNEL_NAME`.

Quick Tunnel подходит для временной проверки. Бигали проверил его на своей сети; на сети Асылбека был таймаут Cloudflare. Для сдачи предлагается отдельный хост по [инструкции деплоя](service/deploy/README.md): личный Mac Даниала нужен для разработки, его не назначаем постоянным сервером. Ноутбук Windows проверяет API/mock; текущий real-движок на нём не работает. Итоговый адрес проверяется вне сети команды.

Docker проверяет API/mock на Linux; **не является способом запуска текущего real MLX-движка**. Сборка: `docker build -t forte-video .`. В Git Bash/macOS ввести ключ скрыто, затем передать Docker только эту переменную:

```bash
read -rsp 'API key: ' API_KEY; echo; export API_KEY
docker run --rm -p 127.0.0.1:8000:8000 -e API_KEY -e VISION_ENGINE=mock -v forte-jobs:/app/runs/jobs forte-video
```

В образ входят API, FFmpeg, контракт, vision, UI и каталог правил. Видео, ключи, результаты и веса не копируются. Внутренний путь для весов — `/app/models`; добавление файлов весов само по себе не делает MLX совместимым с Linux.

## Как проверить решение

```bash
uv run ruff check . && uv run pytest -q
# Сервер должен работать в другом терминале:
uv run python -m service.cli check --synthetic --count 5 --strict --report runs/jobs/smoke.json
uv run python -m service.cli check data/raw/open/videos/X-1.mov --count 5 --strict --report runs/jobs/real-smoke.json
```

Нагрузочная команда выводит job_id, статус, длительности, число нарушений/кадров и движок; ключ и кадры не печатает. `--strict` проверяет точные поля публичного JSON, настоящие JPEG/base64, согласованность вердикта и HTTP 401 без правильного ключа. Код выхода 1 означает провал. Redirect не выполняется, чтобы ключ не ушёл на другой адрес. Синтетическое видео проверяет API и очередь, а не точность распознавания. Удалённый адрес задаётся `--url https://…`; HTTP с ключом разрешён только для localhost.

Пример для Git Bash/macOS, ключ вводится скрыто и не записывается в историю:

```bash
read -rsp 'API key: ' API_KEY; echo; export API_KEY
curl -sS -H "X-API-Key: $API_KEY" -F 'file=@data/raw/open/videos/X-1.mov' http://127.0.0.1:8000/api/v1/analyze
curl -sS -H "X-API-Key: $API_KEY" http://127.0.0.1:8000/api/v1/jobs/JOB_ID
```

| Метод | Ответ |
|---|---|
| `POST /api/v1/analyze` | `200 {"job_id":"…"}`, одно multipart поле `file`, MOV до 200 MiB |
| `GET /api/v1/jobs/{id}` | `processing`/`failed`: только `job_id`, `status`; `done`: также `verdict`, `violations` |
| `GET /api/v1/jobs/{id}/details` | Прогресс 0…1, стадия, имя файла, ошибка, анализ с правилами |
| `GET /api/v1/jobs/{id}/video` | Оригинал; поддерживает Range и HEAD |
| `GET /api/v1/health` | `{"ok":true,"engine":"mock"}` или `real`, без ключа |

Все API кроме health требуют `X-API-Key`, включая details и video. Для плеера UI получает файл через `fetch` с заголовком и создаёт Blob URL. API возвращает `Cache-Control: no-store`.

Ошибки: `400` — поле/формат/пустой файл, `401` — ключ, `404` — задача отсутствует или истекла, `408` — загрузка зависла, `413` — превышен размер, `429` + `Retry-After: 5` — очередь заполнена, `503` — проблема диска, воркеров или FFprobe. При несохранённом результате новые задачи временно не принимаются; после восстановления диска запись повторяется. Неуспешный анализ получает `failed`; причина в `/details`, журнал — `runs/jobs/<id>/worker.log`. UI получает CSP с `connect-src 'self'`, запрещающую отправку API-ключа на другой origin.

## Данные

Конфиденциальные видео организаторов хранятся в `data/raw/`; загрузки API — в `runs/jobs/<id>/`. Оба пути исключены из Git; сервис дополнительно создаёт локальный `.gitignore`. Не используйте `git add -f` для данных. Docker также исключает их. Через 24 часа завершённые задачи и осиротевшие каталоги прерванных загрузок удаляются; срок настраивается через `SERVICE_RETENTION_SEC`.

## Ограничения

- `mock` возвращает заданное тестовое нарушение с реальным кадром: его нельзя выдавать за вывод модели.
- Качество распознавания и скорость на полном видео оценивает danial. Пять синтетических видео не подтверждают скорость ML на 145-секундных роликах.
- Один хост и один API-процесс; после перезапуска незавершённые задачи нужно загрузить повторно.
- Общий ключ подходит для командного демо; пользовательских аккаунтов и разделения доступа нет.
- Локальный лимит — 200 MiB; публичный прокси может ограничивать размер сильнее. Проверьте итоговый маршрут на файлах размера жюри.
- `/health` проверяет живые потоки и отсутствие несохранённых результатов; при проблеме возвращает 503. Совместимость и наличие файлов проверяет doctor, качество и скорость — полный прогон с `VISION_ENGINE=real`.

## Как мы работали с AI-агентами

Правила: [AGENTS.md](AGENTS.md), зоны: [docs/ZONES.md](docs/ZONES.md), задачи: `docs/tasks/`. Каждый агент работает в своей зоне. `bash scripts/sync.sh` получает изменения и показывает доску. `bash scripts/checkpoint.sh "сообщение"` проверяет секреты и зоны, запускает тесты, делает commit и push. При ручном контроле агент готовит изменения, команду запускает человек. Не включайте `autopush.sh` одновременно с ручным режимом.
