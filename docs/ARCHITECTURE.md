# Архитектура распознавания и модели (текст для `docs/SUBMISSION.md`, раздел 3)

> Для жюри и для разработчиков банка. Цифры качества и скорости — только из прогонов `runs/eval/<run_id>/metrics.json` (см. `docs/METRICS.md`).

## Подход: готовые открытые модели + правила, без обучения «с нуля»
В обучающем наборе 40 уникальных роликов и 1–5 примеров на тип нарушения. Обучать на этом нейросеть с нуля или дообучать большую модель бессмысленно: она запомнит одну комнату и не справится с новым ракурсом. Поэтому решение — **гибрид**:

1. **Кадры.** Видео прореживается до 2 кадров в секунду (145-секундный ролик → 290 кадров).
2. **Сцена.** Grounding DINO находит по текстовому описанию стол, ноутбук и сейф на трёх кадрах. Все зоны строятся **от найденных объектов**, а не от координат экрана, поэтому решение не привязано к ракурсу камеры.
3. **Люди.** RT-DETRv2 находит людей на каждом кадре. Лица не распознаются и не идентифицируются: используются только рамки «человек».
4. **Кто где.** Люди у рабочего места делятся на группы по «глубине» в кадре (нижний край рамки). Кассир — группа, ближайшая к ноутбуку и сейфу: они всегда стоят на её стороне. Дальше кассир отслеживается от кадра к кадру. Сторона клиента — люди на другой глубине, при любом ракурсе: сзади кассира, спереди или сбоку.
5. **События по правилам:** кассир ушёл с места, вошёл посетитель, двое на стороне кассира, клиент ушёл, а работа с деньгами продолжается, и т. д.
6. **Проверка VLM.** Локальная Qwen3-VL-4B получает **увеличенные вырезки** кадров события (экран ноутбука, сейф, участки стола) и отвечает на точные вопросы «да/нет»: «на экране открыто рабочее окно?», «дверца сейфа открыта?», «на столе лежат купюры?». Ответы детерминированы (жадное декодирование, температура 0).
7. **Отчёт.** Для каждого нарушения — тип из фиксированного списка, таймкод начала события, 1–3 JPEG-кадра, описание и **норма из проверенного каталога** `data/laws/rules_catalog.json`. Модель не генерирует ссылки на законы: каждая цитата сверена дословно с текстом действующего акта на adilet.zan.kz.

Скорость: детектор людей — доли секунды на кадр (GPU Apple, MPS), около 1 с на вопрос VLM. Вопросы задаются в моменты событий и с редким шагом в остальное время. Время на реальных роликах через API — в `docs/METRICS.md` (замеры без кэша).

## Модели (все открытые, коммерческое использование разрешено)

| Роль | Модель | Лицензия |
|---|---|---|
| Люди на кадрах | RT-DETRv2-R50 (`PekingU/rtdetr_v2_r50vd`) | Apache-2.0 |
| Предметы по тексту: стол, ноутбук, сейф, дверь, счётная машина, сумка | Grounding DINO tiny (`IDEA-Research/grounding-dino-tiny`) | Apache-2.0 |
| Ответы «да/нет» по вырезкам кадров | Qwen3-VL-4B-Instruct, 4 бита MLX (`mlx-community/Qwen3-VL-4B-Instruct-4bit`) | Apache-2.0 |

Версии весов закреплены хэшами в `scripts/download_models.sh`. После загрузки весов интернет не нужен: облачные AI-сервисы и внешние API не используются (раздел 7 ТЗ).
**Сознательно не используем:** Ultralytics YOLO (AGPL-3.0) и модели без явной коммерческой лицензии.

## Где работает
- **Основной хост — Mac на Apple Silicon (M4).** Qwen работает через MLX на GPU Apple, детекторы — через PyTorch (MPS). Сервис FastAPI обрабатывает каждое видео в отдельном процессе с лимитом времени; публичный адрес даёт туннель Cloudflare.
- **Перенос в контур банка (план, не реализован).** Сейчас VLM работает через MLX, а это только Apple Silicon. Для Linux-сервера с GPU NVIDIA нужно заменить слой `vision/vlm.py` на ту же Qwen3-VL-4B (Apache-2.0) через PyTorch/CUDA; детекторы уже на PyTorch. Остальной код и веса детекторов не меняются.

## Как проверяли качество
- Разметка типов для всех 42 роликов (`data/annotations.csv`, 12 типов, `docs/VIOLATIONS.md`). Дубликаты Х-47 = Х-4 и Х-48 = Х-5 считаются одним видео.
- Метрики: вердикт по видео (полнота, ложные срабатывания на чистых), верный тип, таймкод в пределах ±2 с.
- **Двойной прогон:** вся оценка запускается дважды одной командой, результаты должны совпасть полностью (`uv run python -m vision.evaluate --compare RUN1 RUN2`).

_Цифры качества и времени — добавляются после финального прогона (`docs/METRICS.md`)._

## Что распознаёт решение (по обучающим видео, прогон `20261017T2123-fb5e`)

| Тип (поле `type` в API) | Как распознаём | На наших видео |
|---|---|---|
| T1 Ценности оставлены без присмотра | кассир ушла с места (≥ 3 с пусто) → VLM: купюры на столе / Grounding DINO: инкассаторская сумка на столе | Х-15, Х-26 найдены |
| T2 Наличные открыто на столе при клиенте | к столу подходит новый клиент → VLM дважды подтверждает купюры на столе | Х-4 найден; Х-38 — нарушение найдено, тип другой |
| T4 Сейф оставлен открытым | кассир сидит, сейф открыт (VLM по вырезке сейфа, 2 проверки подряд), клиента нет; или сейф открыт после ухода | Х-20 найден |
| T5 Компьютер не заблокирован при уходе | кассир ушла → VLM: на экране ноутбука рабочее окно | Х-11, Х-28 найдены |
| T7 Посторонний в кассовой зоне | двое на стороне кассира (одна «глубина» в кадре) ≥ 2 с | Х-30 найден; Х-18 пропущен |
| T8 Пересчёт не в присутствии клиента | клиент ушёл, кассир остаётся и продолжает работать с деньгами (VLM, 2 кадра) | Х-34 найден; ложное на чистом Х-35 |
| T9 Операция с наличными без счётной машины | купюры на столе при клиенте или из инкассаторской сумки, а VLM ни разу не видит работу счётной машины | уточняет тип в Х-1, Х-4, Х-13 |
| T10 Приём инкассаторской сумки без проверки | посетитель < 12 с, на столе появляется инкассаторская сумка | Х-17 найден |
| T11 Личные вещи на рабочем месте | сумка (детектор) лежит на половине стола кассира ≥ 3 с → VLM подтверждает | Х-40 найден |
| T12 Приём пищи на рабочем месте | стакан/бутылка у кассира (детектор) → VLM: ест или пьёт, 2 подтверждения | Х-46 найден |
| T0 Иное нарушение кассовой дисциплины | запасной тип в каталоге норм для нарушений, не похожих на известные | движок пока не выдаёт |

## Ограничения и известные ошибки
- **T3 «ключ в замке» и T6 «дверь не закрыта» — по косвенным признакам, с малым запасом.** Сами ключ и стеклянная дверь для VLM не видны (Э1, Э2, Э8). T6 — по поведению: в пустую кассу входят и ни разу не разворачиваются к двери спиной к камере ≥ 3 с (правило подобрано на 4 видео, предполагает камеру напротив двери). T3 — по пикселям вокруг замка после ухода кассира (порог по одному видео; на другой камере возможны и пропуск, и ложная тревога).
- **Не распознаём T13 «деньги приняты без удостоверения» (Х-2).** Частичный пересчёт T9 (Х-44) ловим косвенно: кассир одна, после машины не пересчитывает руками (правило на 3 видео). Удостоверение передают в том же жесте, что и деньги, и на 464×848 оно неотличимо от купюр; в чистых Х-35/Х-37 передача выглядит так же (Даниал считает, что удостоверения нет и там — спорная разметка, оставлена как есть).
- **Ручной пересчёт без машины (T9)** сам по себе не выдаём: модель не всегда видит работу счётной машины, и на чистых видео с клиентом это давало бы ложные тревоги. T9 только уточняет тип, когда нарушение с наличными уже найдено (исключение — операция с инкассаторской сумкой).
- **Посторонний, стоящий на стороне клиента** (у двери, пока клиент сидит), неотличим от очереди клиентов → может быть пропущен.
- **Таймкод** — начало события (кассир отошла от места, подошёл клиент). Для T9 время берётся по первому кадру с купюрами и может отличаться от момента пересчёта.
- **Метрики посчитаны на тех же 40 видео, на которых подбирались правила** — это оценка «на обучении», а не независимый тест. Проверка на новом ракурсе — по роликам команды (R11).
- **Затемнённая сцена** (кассир выключила свет) ухудшает ответы VLM.
- Решение — подсказка для проверяющего; вывод о нарушении делает человек.
